# LofiPod's stack

Android-native sideloaded podcast app. Single-user, no in-app feed mgmt (canon in `Sources.kt`). Source-of-truth on `dev` at tag `v0.8.0`.

- **AGP 8.5.2 / Kotlin 2.0.20 / Compose plugin 2.0.20 / KSP 2.0.20-1.0.25.** Top-level `build.gradle.kts` plugins; `app/build.gradle.kts` is the only module.
- **minSdk 28 / targetSdk 34 / compileSdk 34.** Android 9+, R8 minification + resource shrink OFF (R8 broke Media3 audio-sink reflection in v0.3.0 → silent output; keep-rules not yet authored).
- **Jetpack Compose BOM 2024.09.02.** Material3, material-icons-extended, navigation-compose 2.8.1, lifecycle-runtime/viewmodel-compose 2.8.6. All UI is Compose; no XML views.
- **Media3 (ExoPlayer) 1.4.1.** `exoplayer`, `session`, `ui`, `common`, `datasource-okhttp`. Custom `EqRenderersFactory : DefaultRenderersFactory` overrides `buildAudioSink` to inject EQ + skip-silence ahead of Sonic in the audio chain. `enableFloatOutput=false`; int16 to AudioTrack.
- **AudioTrack buffer (DefaultAudioTrackBufferSizeProvider).** 1.5–3.0 s PCM duration, ×8 multiplier (`EqRenderersFactory.kt:55`). Bumped from Media3 default 250 ms to absorb 2× playback DSP jitter; trade-off is ~1.5 s lag before band-slider edits become audible.
- **DefaultLoadControl.** `minBufferMs=180_000`, `maxBufferMs=600_000`, `bufferForPlaybackMs=5_000`, `bufferForPlaybackAfterRebufferMs=8_000`, `prioritizeTimeOverSizeThresholds=true` (`PlaybackService.kt:88`). ~19 MB at 256 kbps stereo. Aggressive to survive network slowdowns mid-2×.
- **AudioAttributes.** `CONTENT_TYPE_MUSIC` (not SPEECH — SPEECH caused BT-only chop on some HALs), `USAGE_MEDIA`, `handleAudioFocus=true`, `handleAudioBecomingNoisy=true`.
- **MediaSessionService.** `PlaybackService` extends `MediaSessionService`; `MediaController` from activity side via `SessionToken`. `MediaSession.Callback.onPlayerCommandRequest` intercepts `COMMAND_PLAY_PAUSE` while autoplay-confirm timer active (`AutoplayConfirmBridge` singleton).
- **OkHttp 4.12.0.** Used for both feed fetches (`PodcastRepository` with browser UA) and the OkHttp-based `LofiPodDownloader` (v0.6.9 rewrite — Media3's offline framework was dropped entirely).
- **Coil 2.7.0.** Image loading; wired with a custom OkHttp client carrying the same browser UA as feeds (cloudfront fronts reject Coil's default).
- **Room 2.6.1 + KSP.** Tables: episode_state, podcast_state, feed_visit, queue_entry, playback_checkpoint, episode_note_entry, episode_kabod, kabod_pack, episode_transcript, auto_download (1h finished / 32h unfinished TTL), lofi_download, episode_scripture (canon index). DB v17.
- **DataStore preferences 1.1.1.** Backs the `Settings` class — theme, EQ CSV, gain, skip-silence level, audio_enhancement_enabled, dc_blocker_enabled, **phase_mode_linear**, autoplay-direction, autoplay-confirm, show_diagnostics_tab_in_player (v0.8.0), etc.
- **WorkManager 2.9.1.** `BackupWorker` (SAF folder, JSON dump, periodic interval picker), `UpdateWorker` (nightly 23:59 GitHub-releases poll).
- **Jsoup 1.18.1.** Used purely on already-fetched HTML strings inside `TranscriptHtmlParser` + per-host extractors (`BethanyExtractor`, `CastosExtractor`, `DesiringGodExtractor`, `SermonAudioExtractor`, `GenericExtractor`). No WebView, no network.
- **ZXing core 3.5.3.** Encoder only; renders BitMatrix → Bitmap for the Settings → Share QR. No scanner, no camera.
- **DocumentFile 1.0.1.** SAF helpers for the auto-backup tree URI + persisted `takePersistableUriPermission` flow.
- **kotlinx-coroutines-android 1.8.1.** `Dispatchers.Main.immediate` for the activity-side PlayerController scope; `Dispatchers.IO` for DB + downloads; `Dispatchers.Default` for the linear-phase EQ kernel-synthesis worker.
- **JTransforms 3.1 (BSD-2-Clause).** Pure-JVM FFT, no JNI. Used exclusively by `LinearPhaseEq` for the optional linear-phase EQ path. Transitively pulls `pl.edu.icm:JLargeArrays` (also BSD-2).
- **Signing keystore.** `app/lofipod-dev.jks` committed to repo (stable cert load-bearing for sideload updates); password from `LOFIPOD_KEYSTORE_PASSWORD` env (CI secret + local shell). Without password, falls back to AGP debug signing.
- **Release pipeline.** `.github/workflows/release.yml`, triggered on `v*` tag push. `versionName` from tag (strip `v`), `versionCode = github.run_number` (monotonic). Builds signed APK + `latest.json` manifest, attaches to GitHub Release. In-app `UpdateChecker` polls `releases/latest/download/latest.json`.
- **EQ chain order (in EqAudioProcessor):** int16 → `Double` drive scale 1/32768 → DC blocker (optional, pre-EQ ~5 Hz HPF) → **biquad cascade OR linear-phase FIR convolution** → master gain (10^(dB/20)) → 2× polyphase upsample (`Oversampler`, 128-tap Kaiser-windowed FIR, cutoff 0.25 of 2×rate) → look-ahead limiter at 2× rate (5 ms LA, monotonic-deque windowed-max peak, -1 dBFS threshold) → 2× polyphase downsample → gated TPDF dither (only when limiter GR > 0) → int16 truncation (clamped to -32768..32767). All scratch buffers preallocated; no allocation in queueInput hot path.
- **AudioChainTelemetry (object singleton).** @Volatile fields for `audioThreadId/Name/Priority`, `priorityDemotions` (AtomicInteger), `passthrough`, `inputPeak/outputPeak` (decayed half-life 0.5 s), `playbackSpeed`. 64-slot ring buffer of (processingNs, audioNs) per buffer → `BufferTimingStats` (avg/p95/max load factor). 50-slot breadcrumb event log (`Event(timestampMs, kind, detail)`) under `eventLock`. Forwards target/actual to `PerformanceHintBridge` once per buffer.
- **PerformanceHintBridge (Android 12+/API 31 ADPF).** Wraps `PerformanceHintManager`. All API-31 types stored as `Any?` so the JVM doesn't resolve them on lower SDK. `ensureSession(threadId, targetNs)` creates/retargets/invalidates-on-TID-swap; `reportActual(actualNs)` per buffer. Defensive try/catch around every API call.
- **Wake lock.** `PARTIAL_WAKE_LOCK` tag `"LofiPod:playback"`, `setReferenceCounted(false)`, acquired on `Player.Listener.onIsPlayingChanged(true)`, released on false + in onDestroy (`PlaybackService.kt`). `wakeLockHeld: Boolean` companion @Volatile mirrors live state for the diagnostics tab.
- **Threading model.** Audio thread = ExoPlayer's playback thread (`ExoPlayer:Playback` typically). Runs `EqAudioProcessor.queueInput` synchronously, including the linear-phase FFT chunks. UI thread = Compose Main. Worker scopes: `LinearPhaseEq.workerScope` (Default), `PlayerController.scope` (Main.immediate), `LofiPodDownloader.downloadScope/cleanupScope` (IO, max 2 parallel downloads via Semaphore).

# Linear phase spec

`app/src/main/java/com/lofipod/app/audio/LinearPhaseEq.kt` (427 lines). Engaged when `Settings.phaseModeLinear=true` AND chain `enabled && !passthroughEffective`. Toggle chips at top of EQ ("Audio Fine-tuning") screen; rehydrated on PlaybackService.onCreate.

- **Type.** Linear-phase FIR via FFT overlap-add. Kernel = symmetric (about its midpoint) → constant group delay across the spectrum → preserves transient waveform shape.
- **Constants.** `KERNEL_LENGTH=4096`, `FRAME_SIZE=1024`, `FFT_SIZE=8192` (next pow-2 ≥ FRAME_SIZE+KERNEL_LENGTH-1=5119), Kaiser β=6 (~60 dB ripple suppression).
- **Group delay.** `(KERNEL_LENGTH-1)/2 = 2047.5 samples ≈ 46.4 ms @44.1k` (≈42.6 ms @48k). Combined with post-gain chain (~6.4 ms = oversampler `(FIR_TAPS-1)/2 = 63.5` 1×-equiv frames + limiter 5 ms LA), **total chain latency ~52 ms in linear mode** vs ~6.4 ms in min-phase mode.
- **Kernel synthesis (per `setBands` call, on `Dispatchers.Default` worker).** Sample biquad-cascade magnitude response at `FFT_SIZE/2+1 = 4097` bin centers via RBJ peaking-EQ closed form (`|H(e^jw)|² = |B|²/|A|²`). Set phase=0, JTransforms `DoubleFFT_1D.realInverse(spec, true)` to get acausal symmetric impulse, circular-shift by `FFT_SIZE/2`, truncate to `KERNEL_LENGTH` taps centered on peak, multiply by precomputed Kaiser window (computed once at class-load via `besselI0(KAISER_BETA*sqrt(1-r²))/besselI0(KAISER_BETA)`), zero-pad back to FFT_SIZE, `realForward` → store in `@Volatile kernelSpectrum: DoubleArray`.
- **Synth-job cancel-on-rapid-change.** `setBands` cancels any prior in-flight `synthJob` so dragging a slider doesn't queue stale syntheses. New kernel published via single `@Volatile` reference swap (audio thread snapshots once per chunk).
- **Initial kernel.** `configure(rate, channels)` calls `synthesizeKernelSync(EqPresets.FLAT)` synchronously → 4096-tap symmetric kernel with peak at center; convolution = identity-modulo-group-delay. So the chain works at first buffer even before any user EQ edit.
- **Convolution (per FRAME_SIZE-sample chunk, on audio thread).** For each channel: copy `inputAccum[ch]` into `workspace[ch]` (length FFT_SIZE, zero-padded), `fft[ch].realForward(ws)`, in-place packed-complex multiply against `kernelSpectrum` (`multiplyComplexPacked` — DC + Nyquist real-only, mid bins full complex mul), `fft[ch].realInverse(ws, true)`. Then `output[0..FRAME_SIZE-1] = ws[0..FRAME_SIZE-1] + pending[0..FRAME_SIZE-1]`, slide `pending` forward by FRAME_SIZE, accumulate `ws[FRAME_SIZE..FRAME_SIZE+tailLen-1]` into pending tail. `tailLen = KERNEL_LENGTH-1 = 4095`.
- **Per-channel state.** `fft: Array<DoubleFFT_1D>` (one instance per channel — JTransforms not thread-safe across instances? unclear; documented as not multi-thread-safe across one instance — used single-threaded by construction here, one instance per channel). `inputAccum: Array<DoubleArray>` (FRAME_SIZE per channel staging buffer). `inputAccumPos: IntArray`. `workspace: Array<DoubleArray>` (FFT_SIZE per channel, in-place FFT scratch). `pending: Array<DoubleArray>` (KERNEL_LENGTH-1=4095 per channel, OLA tail). `outputQueue: Array<ArrayDeque<Double>>` per channel — FIFO of convolved frames.
- **Allocation discipline.** Hot-path `pushFrame/popFrame/processChunk` allocate nothing. **Caveat: `ArrayDeque<Double>.addLast(value)` autoboxes every Double** — implicit per-sample heap allocation on the audio thread (FRAME_SIZE × channels boxed Doubles per chunk → potential GC pressure on long sessions or aggressive ART policy). Kernel synthesis on the worker allocates ~16 × FFT_SIZE = ~128 KB transient (mag array, spec, shifted, kernel).
- **Mode-switch reset.** `EqAudioProcessor.setPhaseModeLinear(on)` flips the @Volatile flag AND calls `linearPhaseEq.reset()` (clears `inputAccum`, `pending`, `outputQueue`). Also called from `queueInput`'s passthrough-exit branch: if `phaseModeLinear` is true and we're exiting passthrough, reset to clear stale pre-bypass tail.
- **NO band-change reset.** `setBands` does NOT call reset. The new kernel's spectrum lands via @Volatile swap; the audio thread continues using `pending` tail accumulated from the PREVIOUS kernel for ~4 chunks (4095 samples ≈ 93 ms at 44.1k) until the tail naturally rolls off. During that window, output samples are convolutions of post-band-change input mixed with pre-band-change tail. Discontinuity is gradual but real.
- **NO cross-fade between kernels.** Min-phase path has a ~46 ms biquad cross-fade (`fadeRemaining` machinery) on band changes; linear-phase path explicitly sets `AudioChainTelemetry.fading = false` and relies on the OLA tail-mix only.
- **Drain on EOS (`onQueueEndOfStream`).** Pushes `FRAME_SIZE * 3 = 3072` zero frames into `linearPhaseEq.pushFrame` to flush the partial accumulator + group delay, then drains the post-gain chain (oversampler + limiter) on top. ~3072 + 64 frames at 1×. Skipped if passthrough or unconfigured.
- **Output frame count != input frame count.** `queueInputLinearPhase(inputBuffer, frameCount)` accumulates input, then `outputFramesAvailable()` is checked and emitted via `replaceOutputBuffer(outputFrames * channels * 2)`. May be 0 (still accumulating) or several thousand. Telemetry `recordBufferTiming(elapsedNs, audioNs)` uses `frameCount` (input) for `audioNs`, not output count — `audioNs` here represents the AUDIO-DURATION of the input buffer chunk, NOT the wall-clock budget for processing it. The v0.7.5 speed-adjustment (`audioNs / playbackSpeed`) is applied downstream in `recordBufferTiming` before passing to `PerformanceHintBridge.ensureSession`.
- **Telemetry on linear path.** Same `pushInputSample`/`pushOutputSample`/`reductionDb`/`ditherActive` instrumentation as min-phase path. `passthrough=false` while linear path runs. `fading` always false. `dspBuffers` increments per call.
- **JTransforms version + format.** `com.github.wendykierp:JTransforms:3.1`. `DoubleFFT_1D(FFT_SIZE.toLong())`. Real-FFT packed format: `spec[0]=Re[0]`, `spec[1]=Re[N/2]`, `spec[2k]=Re[k]`, `spec[2k+1]=Im[k]` for `k=1..N/2-1`. `realForward` is in-place; `realInverse(spec, scale=true)` divides by N internally.
- **Known-suspect surfaces for linear-phase bugs.**
  - Boxing-pressure GC in `ArrayDeque<Double>` (FRAME_SIZE × 2 boxed allocations per chunk).
  - Tail-mix across band changes producing audible discontinuity / brief incorrect EQ.
  - Worker-side IFFT/FFT operating on FFT_SIZE doubles per `setBands` — rapid slider drag triggers cancel-and-restart loop; final synthesis must complete before audible result settles.
  - `@Volatile` swap of `kernelSpectrum` from worker is correct for visibility, but does NOT prevent the audio thread from picking up a new kernel mid-stream where the new kernel's filter response doesn't match the tail of the old kernel still accumulating in `pending`.
  - JTransforms 3.1 last release Jan 2018; the project is effectively unmaintained. No JNI; pure JVM. Potential 32-bit float vs 64-bit float concerns absent (all Double).
  - The progress bar / position reporting from Media3 does NOT account for the ~46 ms FIR group delay — `currentPosition` runs ahead of what the user hears by that amount.
  - Multi-channel: per-channel FFTs run sequentially on the audio thread inside `pushFrame` (one channel at a time). At stereo + 44.1 k, FRAME_SIZE=1024, every 23.2 ms wall-clock the thread does 2 × (realForward + multiply + realInverse) on FFT_SIZE=8192 buffers + 2 × the (Oversampler + Limiter)×FRAME_SIZE chain. CPU envelope at 2× playback gets tight.
  - Initial kernel synthesis is synchronous in `configure` — first audio buffer after a format change blocks on `synthesizeKernelSync(FLAT)` which does FFT + IFFT + windowing. Measurable startup hitch on first play after a track change with different sample rate.
- **Bug-report from user.** "Still buggy in linear phase mode" — symptom unspecified. Candidate symptoms to ask about: pops/clicks on band change, scratchy artifacts at audio start, EQ response that doesn't match the band sliders, audible glitches at speeds > 1×, audio drifting out of sync with progress bar, app stutter on slider drag.
